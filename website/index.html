Eight modules, one contract each.

Every module owns a single responsibility and publishes an explicit, documented contract. No hidden schedulers, no implicit parallelism, no surprise allocations.

corestable

Shared types and errors. No policy, no kernels — the vocabulary every other module agrees on.
runtimestable

Call-bounded scheduler and Shared synchronization. Work is submitted explicitly and joined before the call returns.
memorystable

Bounded Buffer and two-column SoaBuffer. Fallible reservations, no implicit growth, no unsafe.
computestable

Sequential for_each, map, try_reduce, explicit batches, opt-in parallel iteration and composable pipelines — sequential by default, parallel only when you ask.
ecsgrowing

Generational Entity handles, single-owner World, typed sparse-set storage. Component queries and safe parallel systems land in v0.2.
simulationstable

Fixed-step clock, deterministic step contract, replay tests and five bounded models — from ASCII physics to flocking.
networkingfoundation

Blocking TCP wrappers, client-side prediction and reconciliation, a deterministic tick simulator. Wire codec and framing are v0.2 work.
storagestable

Append-only journal with CRC-32 corruption detection: complete corruption fails, an interrupted final write is recovered.
clistable

Manifest-driven projects: init, run, task, doctor and benchmark — with JSON output for scripts and opt-in task execution.

Explicit by construction.

No hidden scheduler

Runtime workers are scoped and joined before any call returns. Nothing runs in the background because you imported a module.

Parallelism is opt-in

Sequential is the default path. Parallel iteration exists, is measured, and is documented as slower for light kernels.

Safety without escape hatches

The whole crate forbids unsafe code. The C ABI exposes only fixed-width scalar queries — no pointers, no buffers, no callbacks.

Measured, not promised.

Real medians from the CI benchmark runs, archived per commit with environment metadata. Microbenchmarks on specific machines — never marketing numbers.

What DINAH is not.

Most readmes list features. This one also lists the missing ones — the same honest limits you will find in the documentation and the security review.

01

Not a physics or CFD engine

The simulation models are bounded educational starting points — explicit limits, no general-purpose claims.

02

No SIMD

SIMD candidates were researched and measured; none justified the complexity for a production kernel yet. Scalar stays the reference implementation.

03

Networking without a wire codec

Blocking TCP exists; framing, the v1 encoder/decoder, auth and TLS are designed and scheduled for v0.2.

04

ECS queries still pending

Individual component access and storage are solid; combined queries and safe parallel systems are the top v0.2 priority.

05

No fuzzing yet

Corruption and robustness suites use a deterministic adversarial corpus — an explicit first barrier, not coverage-guided fuzzing.

06

Pre-alpha, semver 0.x

The v0.1 API surface is frozen, but 0.x permits breaking changes. Adopt with that in mind.

Where this goes.

The v0.2 design is approved and recorded in the repository — priorities come from measured gaps in the frozen v0.1 contract, not from feature envy.
